# 게임 구성과 운영

## 친구에게 보여 줄 첫 화면

프로젝트의 출발점은 학교에서 만난 친구끼리 같은 가상 캠퍼스에 입장할 수 있는지 확인하는 일이었다. 첫 방문자는 닉네임을 정하고 일청담의 자기 캐릭터를 움직인 다음, 친구와 인사하거나 도서관의 자리를 고른다. 카메라와 조이스틱은 작은 화면에서도 캐릭터를 따라다닌다. 게임이 읽는 여섯 장면의 출입구와 보행 영역은 [장면 정의](../public/campus/scenes.js)에 있다.

| 실행 방식 | 연결과 사용 범위 |
| --- | --- |
| LAN 호스트 | 방장 PC에서 Node 서버를 실행한다. 참가자는 방장에게 직접 HTTP 요청을 보내고 SSE로 다른 사람의 상태를 받는다. 서버가 채팅·좌석·공부 기록·친구 광장을 처리한다. |
| 공개 웹 광장 | 배포된 페이지를 열어 체험한다. 직결 모드는 브라우저 간 WebRTC 연결을 시도하고, 웹 모드는 서비스의 웹 경로를 사용한다. 웹판의 방 정원은 4명이다. |
| 혼자 미리 보기 | 수신 주소를 `127.0.0.1`로 지정하면 한 컴퓨터에서 체험할 수 있다. |

### Windows에서 혼자 열기

```powershell
$env:STUDY_BIND = '127.0.0.1'
$env:PORT = '4184'
npm start
```

브라우저에서 `http://localhost:4184/r/main`을 연다. 환경 변수는 이 터미널에서 이어지는 실행에도 적용된다. 친구를 초대하려면 새 터미널에서 기본 `npm start`를 실행하거나 현재 Wi-Fi 주소를 `STUDY_BIND`에 지정한다.

### 행사 운영

- 현재 호스트의 `/health`는 서버 동작 여부, `/api/main/info`는 방 이름·정원·현재 인원, `/r/main`은 참가 화면을 제공한다. 반드시 참가자 기기에서도 입장을 확인한다.
- 초대 QR은 현재 주소·포트·경로를 담는다. 노트북을 다른 Wi-Fi로 옮기거나 주소가 달라지면 초대 메뉴에서 새 QR을 확인한다.
- 같은 무선망에서도 기기 간 통신 정책과 운영체제 방화벽이 다를 수 있다. 학교에서 허용한 네트워크와 지정한 프로그램·포트 범위 안에서 운영한다. LAN 주소는 인터넷 공개 주소로 사용할 수 없다.
- LAN 기본 연결은 HTTP다. 참가자에게 공유한 방 주소만으로 재학생을 인증하지 않는다.

## 저장과 튜터

첫 실행 시 호스트가 `.runtime/study.sqlite`를 만든다. 공부 기록과 친구 광장은 서버 재시작 뒤에도 남고, 접속 인원과 대화는 초기화된다. 브라우저는 기기 프로필과 로컬 기록을 저장한다. 기록 메뉴에서 백업 파일을 내보낼 수 있다. 기기 프로필·복구 식별자가 담긴 개인 백업은 보관용이다. 이 저장소에는 실사용자 DB나 백업 파일을 배포하지 않는다.

튜터를 사용하려면 호스트에 Ollama와 호환 모델을 따로 준비한다. 기본 Ollama 주소는 `http://127.0.0.1:11434`이며 `OLLAMA_HOST`와 `TUTOR_MODEL`로 변경할 수 있다. `TUTOR=off`로 끌 수 있다. 모델 자체는 배포 파일에 포함하지 않는다. 답변은 모델과 질문에 따라 달라진다. [튜터 구현](../src/tutor.mjs) · [Ollama 공식 문서](https://docs.ollama.com/)

## 증상으로 찾는 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 시작 직후 포트 사용 중이라고 나온다 | 이미 실행 중인 호스트를 확인하거나 빈 포트를 선택한다. 기존 노트북 방에 친구가 접속 중이면 그 방은 유지한다. |
| 방장 화면만 열린다 | 친구가 Wi-Fi 주소를 열었는지, `STUDY_BIND`가 루프백으로 제한됐는지 확인한다. 참가 기기에서 `/health`를 먼저 열고 페이지 접근과 게임 입장을 구분한다. |
| 101번째 참가자가 들어가지 못한다 | 메인 광장 정원은 100명이다. 한 명이 퇴장하면 새 참가자가 들어올 수 있다. |
| 웹에서 서로를 발견했는데 직결이 진행되지 않는다 | 연결 제안 교환과 경로 검사를 개별 확인한다. [웹 연결 모드](https://knu-direct-plaza.vercel.app/?mode=web)도 사용할 수 있다. |
| 게임은 되는데 튜터만 응답하지 않는다 | 호스트의 Ollama 실행 상태와 모델 설치·설정부터 확인한다. |
| 도서관이나 강의실로 가는데 이전 장소가 보인다 | 목적지 배경을 내려받아 화면에 그릴 준비를 하고 있다. 준비되면 화면 전체가 바뀐다. 실패 안내가 뜨면 **다시 불러오기**를 누른다. |

## 검증 명령

웹 배포에는 `npm --prefix online run build`로 만든 `online/dist`를 사용한다. 옷장의 기본 문의 버튼은 새 탭에서 이 저장소의 Issues를 연다. 별도 운영 메일을 안내하려면 빌드할 때 `KNU_SUPPORT_EMAIL`을 지정한다. 이 주소는 게임 화면에 공개된다.

```sh
npm test
node scripts/load-event-plaza.mjs 10
npm --prefix online ci
npm --prefix online run build
```

행사판 스크립트는 임시 루프백 서버를 따로 열어 100명 입장과 이동, 채팅, 만석 및 재입장을 검사한다. 웹 빌드 결과는 `online/dist`에 생성된다. 웹판의 참가자 발견과 웹 연결에는 Vercel 함수 및 런타임 캐시가 쓰인다. 정적 파일만 열면 그 기능을 사용할 수 없다. [웹 빌드](../online/build.mjs) · [참가자 발견 함수](../online/api/rendezvous.mjs)

배경 전환은 웹 빌드 후 Chromium 계열 브라우저 실행 파일을 `BROWSER_PATH`에 지정하고 `node scripts/check-scene-loading.mjs`로 검사한다. 데스크톱과 휴대폰 크기에서 네트워크 응답을 1.6초 지연시켜 도서관 입장·강의실 입장·다운로드 실패 후 재시도를 확인한다. [브라우저 검사](../scripts/check-scene-loading.mjs)
